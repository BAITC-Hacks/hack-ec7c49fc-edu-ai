# План frontend-части Astana AI

## Цель и статус

Сделать интерфейс AI-симулятора «Аким на 5 часов» для демонстрации жюри. Пользователь видит проблемы районов, выбирает пять мероприятий в пределах бюджета, запускает расчёт и сравнивает свой сценарий с предложением AI.

- Наша роль: человек 3, Frontend / Product UI.
- Рабочая ветка по сообщению пользователя: `feat/dashboard-ui`. Перед реализацией проверить текущую ветку, самостоятельно не переключать.
- На момент подготовки плана в рабочем каталоге найден только `README.md`; scaffold и общие типы ещё не доступны локально.
- Статус: план подготовлен для обсуждения; реализация не начата.
- Создание этого документа не означает согласование всех будущих изменений кода.
- План рассчитан на 5 часов после появления запускаемого scaffold. Это оценка, а не обещание срока. При меньшем остатке времени сокращать дополнительную полировку.

## Зона ответственности

Мы реализуем `src/components/**` и `src/app/page.tsx`.

Человек 2 отвечает за `src/lib/simulation/**`, `src/data/**` и тесты движка.

Тимлид отвечает за scaffold, общие типы, optimizer, AI endpoint и объединение работы команды.

Не изменять без согласования: `src/types/domain.ts`, `src/data/**`, `src/lib/**`, `src/app/api/**`, зависимости, lock-файлы, глобальные стили и настройки проекта. Корневые `Plan.md` и `AGENTS.md` созданы по отдельному запросу пользователя.

## Зафиксированный стек

Next.js 15+, React, TypeScript, Tailwind CSS. Диаграммы: Recharts. Состояние: React state / useReducer. Тесты: Vitest, если настроен в проекте. Данные: TypeScript/JSON, без БД. OpenAI вызывается коллегой только через серверный Route Handler.

## Правила продукта

- Единый бюджет: 100 условных единиц, не тенге.
- Ровно 5 различных мероприятий из каталога из 14.
- Не более 2 мероприятий одного направления. Не требовать по одному из каждого направления.
- Районное мероприятие требует выбора одного района; городское действует на все районы и не принимает districtId.
- Нельзя превысить бюджет или принять несовместимый набор.
- M1 и M3 несовместимы в любых районах.
- M4 и M7 несовместимы в одном районе.
- M5 и M13 несовместимы в одном районе.
- Все показатели имеют шкалу 0-100, больше означает лучше. Критическое значение строго меньше 40.
- Горизонт модели: 8 кварталов. Срок начала эффекта показывать в кварталах.
- Итоговые показатели, синергии и Score рассчитывает только движок.
- Невалидный набор не получает итоговый Score.
- Проверенные ориентиры: baseline 52.55768; пример M7 Нура, M8 Нура, M10 Нура, M12 город, M5 Сарыарка стоит 95 и даёт 56.54307. Эти числа нужны для проверки, не для подмены расчёта.

## Основной экран

1. Верхняя полоса: Astana Quality of Life Score, изменение, использованный и оставшийся бюджет, счётчик решений.
2. Районы: Есиль, Алматы, Сарыарка, Байконур, Нура; оценки и слабые показатели.
3. Конструктор: каталог инициатив с фильтром по направлению, стоимостью, сроком начала эффекта и областью действия.
4. Выбранный сценарий: список решений, районы, удаление, ошибки, кнопка расчёта.
5. Результаты: Score до/после, горизонтальная диаграмма районов, критические показатели и слабейший район.
6. AI-советник: цель пользователя, статус запроса, объяснение и предложения.
7. Сравнение: текущий план и выбранное AI-предложение, кнопка применения предложения.

Одна страница; допустимы вкладки внутри рабочей области. Не пытаться уместить все 14 инициатив и всю аналитику одновременно на одном экране. Основные показатели должны оставаться заметными.
